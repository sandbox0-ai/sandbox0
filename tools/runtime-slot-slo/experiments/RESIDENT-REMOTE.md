## Retained failures and correction

1. The initial private CLI exited before writing matrix intent or issuing a
   claim. Its base transport config incorrectly combined workload `none` with
   a positive first-command hard limit. The common validator correctly rejected
   that combination. Earlier local mocks used a different config and missed it.
   Preserve the failed unit/log and old binary/fingerprint. A private two-file
   correction extracts the actual base config with no executable gate and sets
   the unchanged2s gate only on executable target configs. A regression uses
   that actual constructor and verifies that the original invalid combination
   is still rejected. Three race repetitions, vet and cross-build pass. No
   product runtime/source or validation rule changes.
2. The original unit was proved terminal, with zero claims/leases and unchanged
   row count, before installing the corrected private CLI. Backup both original
   executable and fingerprint, update only the runner fingerprint, and launch
   a distinct unit. This is not a replay of an ambiguous or live claim. A real
   read-only preflight verifies exact writer, capacity, files, boot, processes,
   Nomad job,8ready and physical absence before the actual run.
3. The corrected run issued nine successful claims, retained two literal-node-v
   results, then failed helper liveness before any phase target. Six helper
   records have context IDs but no verified PID; one transiently reached PID12.
   Final error is `resident context lacks live unpaused clean process evidence`.
   Do not turn transient idle output into evidence of sustained load.
4. Source inspection identifies the fixture contract error: HTTP context Create
   builds `ProcessConfig` without `PipeStdin`; `DirectRunner.Start` creates a
   stdin pipe only when that internal flag is true. `PipeStdin` is not a public
   create field. A non-PTY child therefore receives EOF, and this helper is
   deliberately designed to stop on EOF. An available `/input` route and local
   tests with an explicitly open pipe did not prove that ordinary CMD creation
   supplied one. Existing EOF/signal cleanup tests pass three race repetitions.
   Do not send an invented `pipe_stdin` field or weaken liveness/EOF cleanup.

The next fixture control should use the existing exact-context signal endpoint:
USR1/USR2 are already parsed and sent to the process group. Add an explicit
signal-controlled mode to the bounded helper and adapt only the private control
transport, with actual process/HTTP contract coverage before another matrix.
Keep stdin mode's EOF semantics, fixed lifetime, same-ID phase evidence, strict
host occupancy checks and all original timing/architecture requirements. This
signal-mode change was not implemented or remotely validated in this turn.
