## Changes and observed effect

- Complete matrix orchestration now retains known claim identities even when
  later command, receipt or occupancy evidence fails. An exclusive durable run
  intent prevents restarting the same matrix. Unknown/duplicated claim outcomes
  cannot be silently treated as cleaned or accepted.
- Known-ID cleanup is independently bounded and survives canceled run context.
  Each owned DELETE is attempted once. A lost response triggers only read-only
  absence observation in outer cleanup, not a duplicate DELETE. A receipt write
  failure is retained but cannot prevent the first owned cleanup attempt.
- Added real HTTP/PG/host/verification adapters and entrypoint. Cases and helper
  binary hashes are checked before claims. PG observations require the isolated
  writer authority, exact live capacity, node boot, claim/slot/lease/sandbox and
  resource/RootFS bindings. Left joins prevent hiding an unbound active lease.
  Retiring owned leases can explain pending refill; lost residents, unexpected
  leases, stale readiness or changed authority fail immediately.
- Read-only refill/absence polling retries only a specifically verified pending
  condition. It no longer swallows configuration/query/identity errors as slow
  replenishment. Physical absence also requires local branches/mounts/cgroups/
  NBD empty and the existing pinned global runtime/runsc absence helper. These
  adapters have not yet been exercised against remote PostgreSQL or kernel state.
- Corrected an evidence-parser false-negative before remote use: synchronous
  memory touching/release emits no heartbeat during its phase transition.
  Permit that gap only at idle-to-loaded or loaded-to-released outside target
  windows. Stable-state gaps, expired helpers, missing sequences and target
  bracket checks remain strict. No request/lifetime/SLO budget was increased.
- Collection success is separate from latency acceptance. Retain per-target
  authenticated readiness, full claim, command-only and combined clocks with
  separate1s/2s miss flags. Even a completely collected/cleaned run exits nonzero
  if its2s diagnostic screen fails. The literal executable screen does not
  redefine platform readiness or promise arbitrary program initialization time.
  The CLI never labels this finite private-ingress comparison production acceptance.
